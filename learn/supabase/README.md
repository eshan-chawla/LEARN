# Database Setup Scripts

## Quick Start

### Fresh Setup (Recommended)

Run these SQL scripts in order in your **Supabase Dashboard → SQL Editor**:

| Order | File | Purpose |
|-------|------|---------|
| 0 | `00_DELETE_EVERYTHING.sql` | ⚠️ Optional — wipes all tables for a clean reset |
| 1 | `01_SETUP_EVERYTHING.sql` | ✅ Required — all tables, indexes, RLS policies |
| 2 | `02_SETUP_STORAGE.sql` | ✅ Required — `books` bucket for PDF storage |

That's it. Videos are stored in **AWS S3** (not Supabase Storage), so no extra SQL is needed for video uploads.

---

## Architecture

```
PDF files  → Supabase Storage (books bucket, 50MB free tier limit)
Video files → AWS S3           (no file size limit on free tier)
Metadata   → Supabase Database (classes, recordings, books, notes tables)
```

Videos bypass Supabase's 50 MB free-tier storage limit by uploading directly to S3 via a pre-signed URL generated by `/app/api/upload-video/route.ts`.

---

## What Gets Created

### Tables (`01_SETUP_EVERYTHING.sql`)
- `classes` — Classes created by users
- `recordings` — Video recording metadata (video hosted on S3, URL stored here)
- `books` — PDF documents for classes (stored in Supabase `books` bucket)
- `notes` — Text notes per class (autosaved)
- `pdf_processing_jobs` — Tracks async PDF processing for Lambda/embeddings

### Storage (`02_SETUP_STORAGE.sql`)
- `books` bucket — Private PDF storage, accessible only by the owning user
- Service role access for the Lambda PDF processor

### Security
- Row Level Security (RLS) enabled on all tables
- Users can only read/write their own data
- Service role can update `pdf_processing_jobs` (required by Lambda)

## Troubleshooting

### "relation already exists"
Run `00_DELETE_EVERYTHING.sql` first, then re-run `01_SETUP_EVERYTHING.sql`.

### "new row violates row-level security policy"
The Supabase client isn't sending the auth JWT. Sign out and sign back in to refresh the session.

### Video upload fails with size error
Videos go to AWS S3, not Supabase. Make sure:
- `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, `AWS_S3_RECORDINGS_BUCKET`, and `AWS_REGION` are set in `.env.local`
- The S3 bucket `learn-app-recordings-767398053131` exists in `us-east-1`
- CORS is configured on the bucket (run the setup command from the deployment guide)

### Can't see data after setup
Normal — RLS is working. Sign in to the app, then your data will be visible tied to your user ID.
